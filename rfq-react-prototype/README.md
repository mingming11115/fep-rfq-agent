## 四角色与BU人员范围（2026-10-26）

顶部“演示身份”按真实演示人员切换四种基础角色：后台管理、BU管理员、SR、技术。技术由多名成员组成项目技术组，最终评审是流程职责，不再是第五种基础角色。

主流程：**SR整理应答 → 技术组成员／SR按分派确认 → SR提交快照 → SR与技术组双方通过 → SR正式导出**。SR提交不自动计为SR方通过。技术组可由BU管理员配置为全员通过或指定负责人代表通过，名单、方式及规则版本随快照冻结；退回重提后重新评审。

BU管理员从目录添加／停用本BU成员、设置确认及评审资格、项目访问范围和技术组规则。项目设置的“人员与最终评审”选择SR、技术组、负责人，按条款分派确认责任并设置专业批准人。仅加入BU不会获得所有项目、草稿知识或客户来源文件的访问权。

普通技术成员只能编辑分配给本人的条款；任务转办同步业务对象责任，保留期限和历史。未知归属旧项目不自动授权；旧单人签署快照保留原记录，不能补签冒充新会签。已有示例、人工应答和浏览器存储不重置。

知识与能力发布由获独立资格的BU管理员审核；后台管理维护账号及BU目录。所有身份均为本机模拟，企业登录和服务端鉴权尚未接入。使用 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。

应答编辑移除底部引用证据、操作记录和确认版本面板；评审澄清按“总应答项、未处理、已审核、待确认”统计和筛选。非Comply结论生成推荐话术，可编辑、重新生成并采用为应答草稿，随提交或确认保存。

验证：151项测试通过、生产构建通过；全员模式实际生成正式CSV，代表模式、人员授权、无项目访问拒绝、新建项目确认及任务转办已在隔离存储验收。见[四角色验证记录](../docs/RFQ四角色与BU人员范围验证_2026-10-26.md)。

# FEP RFQ React 交互原型

参考 Ant Design Pro 查询表格的布局和操作方式，使用 React + Vite 实现现有 PRD 与交互设计中的 13 个主页面。界面为中文，数据为模拟数据，操作保存在当前浏览器的 localStorage。

快速使用：[启动说明](启动说明.md) · [演示汇报稿](演示汇报.md)

```bash
cd rfq-react-prototype
npm install
npm run dev
```

打开终端显示的 HTTP 地址，默认 http://127.0.0.1:5173。使用 `npm run build` 构建静态文件到 `dist/`；`npm test` 运行确认、版本、快照与 CSV 相关行为测试。

## 演示方式

顶部“演示身份”可切换销售负责人、技术确认人和最终审批人。专业确认由技术确认人代行演示；最终审批人与提交人分离。更改已确认的答复会撤销原确认，未关闭评审或未完成确认的内容阻止正式导出。

这是交互评审原型。上传只保存文件元数据，解析和检索使用明确标注的模拟结果；没有连接实际 OCR、模型、企业认证或生产数据库。CSV 可以实际下载，正式应答仍须按企业流程复核。知识、资料和能力页面独立保存演示状态，核心“重置演示”保留这些独立记录。

### 2026-10-22 解析与逐条跳转

RFQ解析按当前文件原始章节导航，不做统一要求分类；点击条款标题进入对应细则比对，点击“定位原文”查看摘录，在比对页可返回解析定位本条。载入示例可切换客户一 `.docx`（Safety／Facility）和客户二 `.doc`（反应模块／中转模块），含重复编号、无编号及嵌套章节。现有浏览器数据可通过“载入示例”补齐新样例，无需重置。

边界：本原型保存上传文件的元数据，使用固定模拟结果，未实现真实 DOC 转换、DOCX 读取、结构识别或解析完整性检测；真实解析需按 PRD AC-37～40 使用人工标注客户样本验收。

### 2026-10-23 Word 批注

在「RFQ 解析」页右上角点击「Word批注」，打开按参考图制作的示例文档。支持选中文字后新建批注、页边直接输入并自动保存、彩色选区与连接线联动，以及修改、回复、删除和上一条／下一条定位。关闭、重开或刷新后保留批注，不同项目分别保存。

此入口使用固定示例正文，不读取上传的 Word。批注保存在当前浏览器；「导出预览」展示当前原文、批注和回复的导出范围，暂不生成当前编辑内容的 `.docx` 文件。
