## 三角色功能划分（2026-10-25）

右上角切换身份后，工作台说明、业务资料入口和实际操作权限同步变化。销售可新建和管理 RFQ、维护客户来源与解析、起草提交、跟进澄清、登记客户沟通与验收、配置导出并下载应答；技术可处理专业方案、核对及确认条款、维护知识/机型候选与证据；最终审批人独立批准或退回专业方案、应答快照和业务资料发布。

销售和技术均可提交最终审批快照；正式文件仅由销售负责人下载。技术在应答处理中不能改写客户原文；审批人不能编辑应答或业务资料草稿。来源页向技术与审批身份只读开放。业务资料维护与系统管理分开，三个业务身份均无法进入系统账号与配置页面，旧地址同样受限。

权限与任务处理人、节点资格、对象版本和独立审批规则共同生效；角色切换重建专属表单，保留已保存数据。技术确认人代行质量、商务、服务等专业处理。本机演示校验尚未接入企业认证与服务端授权。

建议按销售起草 → 技术确认并提交快照 → 最终审批退回/批准 → 销售正式导出的顺序验收。完整验证见 [三角色划分验证](../docs/RFQ三角色划分验证_2026-10-25.md)。

## 项目与任务状态（2026-10-24）

项目主状态：**待上传 → 解析中 → 评审中 → 审批完成 → 已导出**。评审中包含应答起草、条款确认、专业评审、客户澄清与最终审批等待。审批完成与正式导出分开；下载内部草稿不改变项目状态。当前内容或来源变化后重新计算状态，历史快照和导出记录保留。

任务状态：**待处理、处理中、已处理**。查看不接手；开始处理或有效保存进入处理中；提交、确认、批准、退回完成对应任务。任务中心分别显示任务类型、状态和结果。退回任务结果为“退回”，上一位处理人收到新修改待办；新快照提交后，修改任务结果为“已提交”。取消、失效只保留历史，转办不计完成。旧浏览器任务自动迁移，无需重置。

## 演示方式

顶部“演示身份”可切换销售负责人、技术确认人和最终审批人。专业确认由技术确认人代行演示；最终审批人与提交人分离。更改已确认的答复会撤销原确认，未关闭评审或未完成确认的内容阻止正式导出。

这是交互评审原型。上传只保存文件元数据，解析和检索使用明确标注的模拟结果；没有连接实际 OCR、模型、企业认证或生产数据库。CSV 可以实际下载，正式应答仍须按企业流程复核。知识、资料和能力页面独立保存演示状态，核心“重置演示”保留这些独立记录。

### 2026-10-22 解析与逐条跳转

RFQ解析按当前文件原始章节导航，不做统一要求分类；点击条款标题进入对应细则比对，点击“定位原文”查看摘录，在比对页可返回解析定位本条。载入示例可切换客户一 `.docx`（Safety／Facility）和客户二 `.doc`（反应模块／中转模块），含重复编号、无编号及嵌套章节。现有浏览器数据可通过“载入示例”补齐新样例，无需重置。

边界：本原型保存上传文件的元数据，使用固定模拟结果，未实现真实 DOC 转换、DOCX 读取、结构识别或解析完整性检测；真实解析需按 PRD AC-37～40 使用人工标注客户样本验收。

### 2026-10-23 Word 批注

在「RFQ 解析」页右上角点击「Word批注」，打开按参考图制作的示例文档。支持选中文字后新建批注、页边直接输入并自动保存、彩色选区与连接线联动，以及修改、回复、删除和上一条／下一条定位。关闭、重开或刷新后保留批注，不同项目分别保存。

此入口使用固定示例正文，不读取上传的 Word。批注保存在当前浏览器；「导出预览」展示当前原文、批注和回复的导出范围，暂不生成当前编辑内容的 `.docx` 文件。
