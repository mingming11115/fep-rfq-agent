## 四角色与BU人员范围（2026-10-26）

顶部“演示身份”按真实演示人员切换四种基础角色：后台管理、BU管理员、SR、技术。技术由多名成员组成项目技术组，最终评审是流程职责，不再是第五种基础角色。

主流程：**SR整理应答 → 技术组成员／SR按分派确认 → SR提交快照 → SR与技术组双方通过 → SR正式导出**。SR提交不自动计为SR方通过。技术组可由BU管理员配置为全员通过或指定负责人代表通过，名单、方式及规则版本随快照冻结；退回重提后重新评审。

普通技术成员只能编辑分配给本人的条款；任务转办同步业务对象责任，保留期限和历史。未知归属旧项目不自动授权；旧单人签署快照保留原记录，不能补签冒充新会签。已有示例、人工应答和浏览器存储不重置。

知识与能力发布由获独立资格的BU管理员审核；后台管理维护账号及BU目录。所有身份均为本机模拟，企业登录和服务端鉴权尚未接入。使用 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。

“机型元数据 / 能力边界”按 **BU → 机型 → 工艺 → 能力条目** 管理。BU管理员可配置所属BU的机型及其工艺，机型修改保留资料版本，工艺支持启用和停用。技术与SR只读机型及工艺配置；技术维护能力候选，提交与发布要求关联本机型下启用的工艺。旧记录不自动猜测归属，保留在“待关联工艺”。页面切换BU重新载入独立数据；导入及项目内补充也保存到所属BU。

应答编辑移除底部引用证据、操作记录和确认版本面板；评审澄清按“总应答项、待处理、评审中、已确认”统计和筛选。非Comply结论生成推荐话术，可编辑、重新生成并采用为应答草稿，随提交或确认保存。

验证：151项测试通过、生产构建通过；全员模式实际生成正式CSV，代表模式、人员授权、无项目访问拒绝、新建项目确认及任务转办已在隔离存储验收。见[四角色验证记录](../docs/RFQ四角色与BU人员范围验证_2026-10-26.md)。

## 演示方式
