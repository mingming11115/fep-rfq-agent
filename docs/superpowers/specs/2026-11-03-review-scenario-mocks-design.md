# RFQ 评审阶段 mock

用户要求新增几套独立 mock，并明确“部分评审”指部分条款已确认、其余条款待评审。当前 RFQ-001 的整轮最终评审已按用户指令完成，新增数据必须保留该轮记录。

## 场景

- `partial-review`：4 条模拟应答，2 条已确认，2 条进入指定技术人员的评审。
- `ready-final`：4 条应答已确认，证据、条件及人员配置完整，无快照，可直接发起最终评审。
- `approved-final`：4 条应答已确认，有 SR 与指定技术组全部通过的当前有效快照，可由 SR 正式导出。

## 实现选择

采用独立项目和独立的一次性补入机制，复用现有人员资格、确认、快照和最终评审规则。项目名称、答复、依据与历史记录均明确标注模拟。这是实现选择，不新增业务阶段或改变审批规则。

沿用当前 checkout，保证正在运行的 5173 页面能直接验收。已有浏览器启动时备份并增量补入；新浏览器和重置演示也包含这些场景。完成标记使刷新不会重建用户修改或删除的案例。只在有效的 BU-DEMO 演示人员范围内添加，不修改成员资格、其他 BU、已有项目或审批。

## 验收

场景能由现有选择器和任务生成逻辑识别；待发起场景所有提交校验通过；已批准场景通过当前快照有效性与导出检查。迁移可重复执行、保留已有数据，并在存储写入失败时恢复原值。浏览器实际展示三套新案例。
