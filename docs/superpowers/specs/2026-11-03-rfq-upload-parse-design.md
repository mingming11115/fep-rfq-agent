# RFQ 上传、模型解析和 OCR 降级

用户已选择可配置通用接口。沿用 Spring Boot / MyBatis、DOCX / PDF 与现有鉴权接口，不改前端。

采用原生读取 → 图片/扫描页 HTTP OCR → 兼容 Chat Completions 抽取 → 来源校验 → 保存。另一方案是把完整文件交给供应商托管解析，会绑定厂商且难以独立降级，故采用现有读取器加适配器。

模型、OCR 独立开关、完整端点、Bearer 密钥、连接/请求超时。默认关闭，关闭模型时使用规则，开启模型但失败时退回规则并提示；OCR 关闭或失败保留图片占位，解析标记 partial，不伪造识别文本。OCR 成功文本保留锚点和 ocr 来源，抽取条款需核对。仅做 HTTP 通用协议，不自动安装本地 OCR 引擎。

模型分批请求；校验引用块、逐字摘录与必填字段，不采纳无法验证的模型输出，失败批次退回规则。未覆盖内容不能静默丢弃。运行记录持久化实际抽取器和降级信息，POST/GET 一致。

上传校验真实 DOCX/PDF 内容，原件不可变、大小受限、失败清理文件；新增受鉴权的原件下载。重复解析先完成读取/抽取再替换，已有人工修改/确认时拒绝重解析；同文档串行，避免覆盖与重复。

验证使用真实生成 DOCX/PDF、HTTP 假服务模拟成功/超时/错误/非法引用、数据库集成和全套 Maven 测试。没有真实模型/OCR 凭据时不声称完成供应商实网联调。
