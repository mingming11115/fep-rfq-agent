# B09 项目维护设计

用户在基础管理完成后要求继续下一个功能，按验收清单顺序实现 B09。沿用现有 rfq-service、MySQL、JWT、统一响应和审计，保留上一批未提交代码及其他任务的前端暂存内容。

## 范围与选择

本轮交付项目基本信息修改、负责人移交、归档与恢复，以及分页查询和归档写保护。采用服务端事务动作扩展现有项目资源；不增加通用 stage 修改接口，也不物理删除项目。直接开放阶段 PATCH 会绕过后续确认/批准流程，故按已有接口规范采用动作资源。

基本信息包括名称、客户、截止日期（ISO 日期），截止日期通过新迁移 V4 保存。机型/工艺结构属于 B20，不引入未经定义的配置字符串。本轮支持 DRAFT/PARSING 的现有业务阶段和 CANCELLED 归档；REVIEWING/APPROVED/EXPORTED 为后续流程保留，不能通过项目维护伪造批准或导出。解析任务仍维持既有行为，不把某次解析完成当作整份 RFQ 已经评审完成。

## 接口与权限

- PATCH `/projects/{id}`：必填 version、reason，允许部分修改 name/customer/deadline。未传字段保留；customer/deadline 显式 null 可清空；名称不可空。name/customer 最长 200，reason 非空最长 500，version 为非负整数。code/buId/ownerId/stage 等额外字段一律 400。
- POST `/projects/{id}/handovers`：version、reason、ownerId。接收人须为同 BU 启用的 SR，且已经获得项目访问授权。本人/原负责人相同的移交返回 409。移交改变 ownerId，保留双方已有项目成员授权；原负责人失去项目管理/再移交权限，其他既有 SR 参与权限不自动删除。
- POST `/projects/{id}/archives`：version、reason。活动项目设为 CANCELLED，保存归档前阶段、时间、操作人及原因。已归档或不认识的旧阶段返回 409。
- POST `/projects/{id}/restorations`：version、reason。仅 CANCELLED 可以恢复为保存的原阶段；缺少可靠原阶段的旧记录返回 409。清除当前归档标记字段，历次原因与阶段变更保留在审计。

上述业务维护仅当前项目负责人且具有本 BU SR 角色，或本 BU 管理员执行。技术、其他 SR、纯平台管理身份均不自动获得业务维护权。沿用项目访问保护；平台仍可维护授权元数据。

GET `/projects` 默认 archived=false，只返回可见活动项目；archived=true 只查可见归档项目。两个分支都在 SQL 过滤后计数/分页，可按 keyword（编码/名称/客户）、stage（白名单）过滤。GET 详情和历史原件保持原有项目权限，归档不删除任何关联数据。stage=CANCELLED 与 archived=false 组合返回空页，查询零副作用。

## 一致性和写保护

所有维护操作锁项目行，先校验权限，再比较请求 version；更新 SQL 同时带旧 version，成功递增一次，审计加入同一事务。归档、移交、项目授权和原件上传共用项目锁。

归档暂停基本信息、移交、来源上传/示例上传、触发解析和人工条款修改。读取与安全授权维护继续允许，管理员可以撤销归档项目的访问。解析及条款修改新增项目行锁并统一使用“项目 → 文档”顺序，避免归档后仍提交业务修改或与上传形成反向锁死。解析仍为同步，归档会等待已开始的解析事务结束。

归档前阶段及操作者字段只由服务端写入。没有通用 DELETE 或任意状态覆盖。审计包含动作、原因、旧/新负责人或阶段以及版本变化；不把整份来源正文写入事件。

## 验证

实施补充：项目 FOR UPDATE 查询刷新 MyBatis 本地缓存并禁用二级缓存，保证锁定读取真正访问数据库。数据库悲观锁等待失败统一返回 409。并发测试使用数据库锁等待超时与受控 SQL 调度确定顺序；独立读取事务校验提交结果。写保护范围为 `/api/rfq`，独立 craft/office 项目接入维持 B23 范围。

复查修正：MySQL REPEATABLE READ 中先查文档会开启旧快照，取得项目锁不会自动刷新快照。因此重解析的人工版本保护必须通过条款当前锁定读取执行，锁顺序为项目→文档→条款；新增真实提交等待回归验证人工条款不被删除或替换。

使用独立 MySQL 8；先验证上一批 85 项基线。新增真实 HTTP/Mapper 测试先失败再实现，覆盖：部分字段保存与清空、非法字段、负责人资格及已有项目授权、移交后权限变化、版本冲突、归档列表 total、归档保留下载/条款/解析结果、所有归档写入口拒绝、恢复后的原阶段、失败不写成功审计、实际并发归档与业务修改的串行。全量 Maven verify 通过后更新 B09 清单、接口说明和产物。生产部署、远程推送及前端业务页面接入由后续请求处理。
