# B10 原件上传、版本、校验与下载

用户要求按清单继续下一项，范围为 B10。基于 B09 完成后的 103 项基线，完善现有文档链路并补充验收；不重建文件服务，不修改前端暂存、不部署或推送。

## 方案与边界

保留现有 DOCX/PDF 原件按不可变文档 ID 存储、项目内递增上传版本的语义。每次上传均为独立记录，即使内容相同也不覆盖旧版；不按文件名猜测版本链，不做 B12 的条款映射或 B23 的批阅共享。采用现有事务/存储服务逐项补齐，比另建对象存储或整包内存下载更符合当前部署与流式下载能力。

单文件上限 **30 MiB（31,457,280 字节）**，同时校验声明大小和真实流长度，拒绝空文件、伪造格式、损坏或加密 PDF。保留已有真实格式读取器。清理客户端路径和控制字符后，文件名最多 255 字符，与数据库一致；支持中文、空格及扩展名大小写。

验证通过后由服务端确定 MIME，不信任 multipart 的 Content-Type。DOCX 为 application/vnd.openxmlformats-officedocument.wordprocessingml.document，PDF 为 application/pdf。新增 GET /documents/{id} 返回与列表/上传一致的元数据，包括 contentType，不返回内部 storageRef。未知 ID 404；详情、列表、下载统一复用项目读取权限，归档仍可读。

## 版本与不可变性

两种上传入口均先锁项目，再用当前锁定读取取得最近文档版本并分配下一版本；不使用可能过期的 REPEATABLE READ 普通列表快照。最新版本已为 Integer.MAX_VALUE 时返回 409，不溢出。新增 V5 唯一索引 (project_id, version)，索引遇到历史重复时明确阻止迁移，不自动改历史编号。

解析状态写入仅允许改变 status，不能通过通用 Mapper 更新原件名称、版本、用途、路径、类型、大小、哈希或上传者。旧版本可以独立下载。上传失败或事务回滚清理原件/暂存文件，并回滚记录、项目版本/阶段和成功审计；失败不消耗上传版本。

下载前按登记 sizeBytes/SHA-256 执行有界流式校验，缺少原件返回 404，元数据缺失或大小/哈希不符返回 409，不将损坏文件当作成功结果。保留 FileSystemResource 流式响应、HTTP Range/HEAD、attachment、no-store 和 nosniff；返回规范 MIME、长度及 SHA-256 ETag。原件目录属于本服务管理范围，本轮校验针对下载开始前的完整性，不新增内存整包或临时副本协议。

## 验收

首先运行 103 项基线。新增真实 MySQL/MockMvc 测试先失败再实现，覆盖：文件名上限、MIME、详情、历史下载、独立哈希、状态更新不可改原件、损坏/缺失下载、分页权限、回滚清理、旧快照分配、真实并发版本及数据库唯一性；存储测试覆盖 30 MiB 边界和流长度谎报。增加真实 HTTP multipart 超限验证（MockMvc 不执行 Servlet multipart 限制），统一 413 中文提示。

最终完整 verify 与新空库 V1–V5 初始化通过后更新 B10 清单、接口文档、JAR，保留 V1–V4 及原暂存内容。线上历史缺少 SHA/大小或重复版本需核对修复后再部署，本轮不会在 GET 中悄悄补写或重编号。
