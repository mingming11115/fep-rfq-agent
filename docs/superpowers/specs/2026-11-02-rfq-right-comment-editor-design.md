# 统一批注编辑位置（第 5 项）

用户已选择“统一到右侧协作记录，页边只看摘要”，并要求继续按照 list 修改、每项独立提交并合并到 master。新增、回复、修改、解决/重开及现有删除权限统一放在右侧；转评审和原文定位继续保留。页边只显示作者、批注摘要、回复数量、解决状态和原文锚点/连线，点击打开右侧对应讨论。右侧分区仍名为“协作记录”。

已讨论的替代方案是统一到原文页边或保留两处完整编辑，用户未选择。实现沿用现有 React 批注面板及原生消息桥，不修改原生引擎、正文权限、定位算法或顶部 Discord 的既有处理。

原文选区的新增批注先由原生引擎建立真实锚点，随后在右侧填写同一条批注；原生编辑请求同样转入右侧。只对这次明确新增的批注，根据非空摘录在同文件/版本条款中唯一包含且有权限时关联；没有唯一条款时显示待关联入口，由用户选择，不能套用当前条款。既有未关联文件批注不自动归属。未编辑的空白文件批注不会批量导入协作记录。

待关联批注也在右侧提供原有权限下的文件批注编辑、回复、解决和删除，未关联前不建立条款协作记录。取消新空白批注无需先关联。文件保护和身份变化会禁用操作，过期文件或过期讨论回调不能关闭新讨论。原生复用已删除批注的编号时，旧讨论保留为历史删除记录，新批注使用新的讨论身份，不继承旧评审链接；原生撤销仍可恢复旧批注。

页边摘要不显示编辑框、回复框、操作菜单或完整回复列表。右侧保留 @提及、原作者、回复、保存/同步状态及转评审。点击既有摘要只打开对应讨论；明确的新建或编辑请求才进入右侧编辑状态。取消空白的新批注会删除该空白批注；取消已有文字的修改保留原内容。文件/条款/身份切换不能把编辑输入带到其他目标，过期文件消息不能打开或修改当前讨论。

右侧编辑请求在处理后即消费，切换分区重新打开讨论时不重播旧请求。

继续保留 Word/PDF 文件中的真实批注、保存失败恢复和只读查看。独立 Demo 使用原来的页边完整编辑，仅 RFQ 项目启用摘要模式。其他 outputs 成果与本项无关，不纳入提交。
