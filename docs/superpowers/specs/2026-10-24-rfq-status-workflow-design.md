# RFQ 项目与任务状态调整

用户已确认本次修改，沿用现有 React 原型及浏览器数据。

## 状态规则

- 项目主状态只有：待上传、解析中、评审中、审批完成、已导出。
- 无要求来源、无条款为待上传；要求来源排队、处理中或失败待解决时为解析中；有可处理条款后为评审中，包含起草、确认、澄清及最终审批等待。
- 当前有效快照批准且条款全部确认、无未闭事项时为审批完成；该快照成功正式导出后为已导出。内部草稿下载不改变项目状态。
- 来源、答复、配置、模板或映射变化后，旧批准和旧导出保留历史，当前项目重新按实际工作状态展示。
- 任务状态：待处理、处理中、已处理。查看不接手；开始处理或保存有效编辑进入处理中；保存不完成任务。
- 任务类型、状态和处理结果分列。结果包括已提交、已确认、批准、退回、澄清已解决。
- 退回是审批任务的处理结果，审批任务已处理；上一位处理人收到新的待处理修改任务。
- 转办换处理人并回到待处理，保留期限和历史，不计为已处理。取消、失效留在历史，逾期只是提醒标签。

## 实施选择

统一状态计算与任务数据迁移，并在原有任务页增加结果列。仅替换页面文案无法覆盖审批与导出拆分、退回新待办和旧数据恢复，因此不采用。

文档文件仍保存在已有独立存储中，同时将文件元数据同步到应用汇总，刷新或跨页面后项目状态一致。最终审批退回生成快照修改任务，重新提交新快照时完成该任务；专业评审继续使用现有新轮次机制。
