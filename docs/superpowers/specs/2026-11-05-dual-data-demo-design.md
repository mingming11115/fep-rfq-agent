# 两套独立数据展示入口

## 目标与已确认选择

用户要求保留一套前端模拟数据展示，并增加一套 MySQL 数据展示，后端启动时插入演示数据。用户已选择“两套独立启动入口”。沿用现有 React/Vite、Java/Spring Boot 与 MySQL；完整模拟应用与数据库数据查看页各自使用适合的数据模型。

## 启动与数据边界

- `npm run dev:mock`：前端模拟版，默认 `http://127.0.0.1:5173`。无需登录、MySQL 或后端即可浏览现有八个项目、应答矩阵和三套评审场景；身份切换仅用于模拟。保留现有浏览器数据，新增数据使用独立存储命名空间。
- `npm run dev:mysql`：MySQL 展示版，默认 `http://127.0.0.1:5174`，连接独立演示后端 `48084`，保留已有 `48083` 服务。保留后端登录，登录后从 MySQL 读取数据。页面明确显示当前版本。
- `npm run dev:api:demo`：启动演示后端；开发环境启用演示初始化。首次初始化检查已有标识，只插入缺失记录；完成后通过种子标记跳过，保留后续人工修改和删除，不覆盖已有账号或项目。

## 数据方案（按用户后续指示更新）

用户后续明确要求“你直接直连数据库吧，给我一套数据库的模拟数据”，停止方案提问。MySQL 版通过现有 Java 后端连接 MySQL，把演示 BU、五个账号、八个项目、原件、解析条款和项目授权实际插入现有业务表，不使用演示快照表。页面提供项目列表、项目原件、条款和成员的数据库展示，支持下载原件及按现有接口修正条款；尚无业务表的模拟评审和批准快照仍在完整前端模拟入口体验，不伪造其落库。

两套入口使用不同端口隔离缓存、登录和操作。MySQL 连接或加载失败时显示错误及重试，不回退到前端模拟数据。前端模拟入口跳过真实登录与人员同步，不调用真实账号管理、上传和解析接口；涉及真实服务的操作给出明确提示，创建项目留在浏览器。MySQL 页面按现有后端权限读取数据。

## 方案取舍

- 已选择：两套启动命令和端口。数据来源与缓存边界清晰，可同时打开对照。
- 未选择：单站内切换。操作方便，但更容易混淆身份、数据源与缓存。
- 用户后续选择：直接写入现有业务表，提供能查库核对的数据展示；保留现有权限。

## 验收

1. 关闭后端时，前端模拟版仍能进入八个演示项目并切换模拟身份。
2. MySQL 版必须从后端返回的数据展示；后端离线时有错误提示，不冒充数据库数据。
3. 首次启动后 SQL 可查询到完整种子；再次启动行数不增加、已有编辑不被恢复为初值。
4. MySQL 版条款修正后刷新仍从库中回读；旧版本保存沿用现有乐观锁冲突提示。
5. 两个入口同时打开时，模拟版操作不改变 MySQL 数据，MySQL 登录也不会清掉模拟项目。
6. 运行有针对性的前端和后端测试、构建，并在可用的本机 MySQL 上实测启动与重启。
