# BU 机型与工艺配置

用户要求：每个 BU 有自己的机型，机型下面有工艺，由 BU 管理员配置。

- 在当前 React 原型“机型元数据 / 能力边界”中落实 `BU → 机型（硬件版本）→ 工艺 → 能力条目`。BU 管理员只能配置获授权 BU 的机型和工艺；SR、技术只读机型及工艺配置。
- 机型元数据作为 BU 配置直接保存生效，保留配置版本；工艺包含编码、名称、适用条件和启用状态。停用保留历史关系。
- 技术继续维护能力候选，能力必须关联本 BU、本机型下启用的工艺才能提交审核或发布；现有独立能力发布资格和不可自审规则继续生效。
- 能力按工艺筛选，详情、编辑、导入和项目内补充使用一致的归属。旧能力没有工艺 ID 时显示“待关联工艺”，不根据文本猜测，也不丢弃。
- 继续使用现有 React、BU 存储键和浏览器保存；切换 BU 时重新载入本 BU 数据，空 BU 可从新建机型开始配置。本次不接入企业后端。
- 采用显式工艺实体及稳定 ID，避免仅在条件文本里填写工艺造成无法筛选和权限校验；不引入全局共享工艺字典或额外审批流。
- 现有机型的硬件版本不可变更；新硬件版本须新建机型，避免自动继承原有工艺和能力。项目内补充显式选择所属BU的机型及工艺，不根据设备范围自由文本猜测硬件版本。调整导入能力归属后重复导入也不创建相同ID的候选。
