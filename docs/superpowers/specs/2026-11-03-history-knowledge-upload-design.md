# 历史 RFQ 文档上传与条款知识

用户已确认本聊天中的字段和文字交互方案。本文件记录该方案及实现选择。

## 目的与范围

历史 RFQ 以文档为入口：上传 → 自动解析为草稿 → 核对文档信息和条款 → 批量提交 → 独立审核发布。一份文档关联多条知识。

文档元数据包括客户、项目、机型、配置、日期、文件版本、BU、可见范围。条款包括原编号、章节、客户要求、历史答复、适用条件与限制、原文定位、证据和客户反馈／验收结果。历史答复包含结论和说明，不新增应答结论字段。原文没有的信息保持空白。

## 页面与状态

历史 RFQ 首页每份文档一行，支持搜索条款并进入对应文档。上传弹窗选择 DOCX/PDF，可追加同一 RFQ 的配套答复文件。选择文件后上传并解析，创建可返回的记录。详情顶部统一维护文档信息；下面显示完整、缺答复和异常条款统计及条款表。点击条款在宽面板中对照来源和编辑字段，支持上一条／下一条以及要求／答复分别定位。异常块保留，可补录。原件可下载。

解析结果自动保存为草稿。缺答复允许保存，不允许提交。审核沿用现有知识发布权限与同版本不得自审规则。文档解析状态与条款审核状态分别展示。重新解析按来源定位合并，保留人工修改和已提交／发布版本，不静默删除旧条款。重复上传同内容同配套答复提示打开已有文档。

## 方案选择

已选择文档列表与独立详情页；上传使用轻量弹窗。整份文档放在原新增知识弹窗中会难以核对大量条款。手工维护仍用于补录单条知识。

## 实现选择

沿用 React 19 / Ant Design / Spring Boot。现有知识库为本地原型存储，因此文档元数据、条款与审核沿用同一 BU 本地存储；原件存 IndexedDB，真实解析使用带登录鉴权和 BU 校验的专用后端接口，临时文件解析后清理。浏览器页面内导航不取消解析；刷新遇到未完成任务时提示重试。共享数据库知识服务不在本次范围，不能把本地审核描述为生产级跨用户协同。

复用 DOCX/PDF 读取器与 OCR。历史抽取单独识别要求／答复列及显式答复段落，不套用只抽要求的现有逻辑。配套答复只按唯一原编号对齐；重复或无编号时保留为异常，交由人工关联。PDF 无法可靠分栏的段落保留为待核对，不能编造历史答复。

## 验证

真实 DOCX/PDF 生成样本测试：分列答复、单独结论加答复列、缺答复、重复编号、配套答复、扫描占位与错误文件。前端测试覆盖保存、重试合并、搜索、权限、自审阻止和跨 BU 隔离；全套前端测试与构建、后端测试、浏览器上传走查。
