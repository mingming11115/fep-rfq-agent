# 应答确认与多人评审

用户已在对话中确认并要求实现以下设计。

- 普通应答项由项目 SR 默认确认；直接指派后由指定人员确认。
- 发起专项评审时选择一位或多位具体评审人；全部评审人确认同一版本后，应答项已确认，事项已关闭。无需 SR 再确认。
- 取消专项评审批准人及独立批准节点；保留整份 RFQ 最终评审。
- 发起表单保留评审类别、问题说明、评审人（多选）及截止时间。
- 所有业务入口权限一致。显示真实姓名、逐人确认状态及具体阻塞原因。
- 应答内容、评审方案或评审人员变化使旧确认失效；保留历史记录。旧数据迁移保留显式分派与历史，默认生成的技术确认人恢复 SR 默认。
- 实现选择：沿用项目授权及有效人员资格，普通项目 SR 无需额外确认资格；评审人使用本项目有效确认人员；多人共同编辑一份应答，以版本检查防止覆盖。

## 实现补充

- 评审类别使用技术、质量、商务、服务、其他；历史类别继续显示。
- 普通保存、人员调整不能丢弃旧版待核对建议；只有明确采用或说明保留原因后才能继续确认。
- 旧版部分人员分派审计只有 BU 和接收人、缺少条款标识。此类证据不足的分派保守保留，在项目人员配置显示说明并允许恢复默认 SR。
- 已确认历史行保持原内容以保留最终快照有效性；另行记录隐式默认分派，后续确认采用项目 SR。
- 按项目执行幂等迁移，撤销删除后恢复的旧项目同样迁移。

- 与 master 集成时保留统一评审入口，旧客户澄清转为多人评审结构并保留历史回复；关联证据仅接受 http/https 链接。
