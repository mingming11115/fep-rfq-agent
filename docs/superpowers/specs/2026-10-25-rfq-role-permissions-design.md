# 三角色功能划分

用户在确认销售负责人、技术确认人、最终审批人的业务分工及当前权限缺口后，明确要求“划分”。本次落实已讨论的分工，沿用 React 原型、当前目录及浏览器数据。

## 规则

| 功能 | 销售负责人 | 技术确认人 | 最终审批人 |
| --- | --- | --- | --- |
| 项目创建、移交、设置、客户新版、来源文件及解析修正 | 操作 | 查看 | 查看 |
| 起草提交 | 起草并提交 | 接到确认任务后修改核对 | 查看 |
| 专业方案、条款确认、采用建议 | 发起事项；客户澄清跟进 | 处理方案；核对采用；确认条款 | 批准或退回方案 |
| 最终审批快照 | 提交 | 提交 | 独立批准或退回 |
| 内部草稿和正式 CSV 下载、导出映射设置 | 操作 | 查看 | 查看 |
| AI 分析记录及重新匹配 | 查看、按条款任务重新匹配 | 查看、按条款任务重新匹配 | 不开放分析入口；可查看已有依据 |
| 标准回复、机型能力、证据资料 | 查看 | 新建、修订、提交候选；维护证据 | 审核发布、退回、撤销；不编辑候选 |
| 审计 | 项目协作记录 | 项目协作记录 | 审计查询 |
| 系统账号、管理身份、系统配置 | 不开放 | 不开放 | 不开放 |

业务角色与节点资格、当前任务归属、对象版本及独立审批同时校验。销售或技术提交快照保持现有流程；技术确认不自动等于方案批准；最终批准不自动导出。

## 实现方式

采用共享权限模块，菜单、按钮、页面入口及实际操作处理器使用相同规则。仅隐藏按钮无法覆盖旧链接和操作回调；为每个页面复制规则容易遗漏。共享策略配合既有任务校验可以保留现有业务流转并封闭缺口。

全局菜单按角色提供业务入口；业务资料与系统配置分离。角色切换后清理未提交的角色专属表单；非法深链接显示无权访问及返回工作台。来源浏览和历史快照保留可读。

## 验证

先为拒绝跨角色操作、合法交接和深链接写回归测试并确认失败，再实现。执行全量测试、构建、浏览器三角色与正常/退回流程验证；不重置已有演示存储。交付仍为本机交互权限，企业认证和服务端授权不在本次范围。
