# 应答与问题处理统一工作区

用户要求直接修改现有原型，合并应答项与评审澄清，并在通过／确认后自动进入下一条。参考 Linear Triage 的队列处理和 shadcn Mail 的分栏布局。

- 单一「应答项处理」tab；条款队列、原文、当前应答联动。评审和澄清在当前应答内显示，项目全部事项可集中筛选处理。
- 主要操作固定在处理区下方；未修改且有效的应答一键确认，修改过的内容继续要求原因；SR提交技术确认后同样进入下一条待提交项。
- 下一条以当前队列顺序为准，从当前位置向后找本人可处理且未完成的条目，队尾仅回找一次；不能循环到刚处理的条款。待评审和澄清不自动确认。
- 展示成功反馈、下一条预告和本轮完成提示。反馈可返回刚处理的条款核对；撤回确认仍走现有编辑复核机制。
- 旧评审路由、任务深链、原文版本、未保存编辑拦截、角色权限、最终评审及导出门禁保留。跳转下一对象时清除旧任务和评审上下文。
- 在当前干净工作区新分支实现，不安装新UI依赖，不修改既有浏览器业务数据。

实现采用队列辅助函数和独立展示组件，复用现有事项处理抽屉。直接堆叠两个旧页面会保留重复筛选和切换；另起独立审批流程会割裂现有任务和门禁，因此不采用。
