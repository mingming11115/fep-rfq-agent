# 分组驱动知识库 Implementation Plan

Goal: 左侧分组树组织知识库，右侧回复/历史RFQ/能力资料可多分组关联，创建RFQ必须选择启用分组。
Architecture: 共享 GroupWorkspace/Context 提供 BU 隔离目录和选中分组；资料 groupIds 记录多分组，旧 groupId/能力关联兼容读取。权限过滤先于分组筛选；不以分组授予权限。历史文档归组同步条款，保留来源与审核版本。RFQ保存分组快照且取消新建时旧目录旁路。
Tech Stack: React、Ant Design、现有 localStorage 与历史原件存储。
Spec: 本会话用户确认的左树右内容与资料多分组方案。

- [x] 领域规则：归组读取、显式空归组、跨BU与停用校验、历史资料兼容；先失败测试再实现。
- [x] 共享分组工作区与多选组件、路由保留分组、分组维护。
- [x] 回复/历史RFQ/能力按分组筛选，新建默认归组与多关联编辑，保留原审核规则。
- [x] RFQ创建必选分组、移除旧目录绕过，历史RFQ兼容读取。
- [x] 领域和界面回归、生产构建、浏览器验证与独立复核。

Constraints: 不跨BU，不授予额外项目权限，不自动发布资料，不自动重写旧资料，不提交推送。
Review focus: 未分组资料、显式移除关联、多分组去重、停用祖先、切换BU/分组、上传去重和文件版本、隐藏详情/编辑弹窗、创建RFQ缺失分组。

Validation: 全量前端512项通过，新增历史兼容/归组规则10项定向复验通过；生产构建通过；隔离Chrome验证分组筛选、多选关联、三页签、窄屏及RFQ提交必选分组。独立复核后修正未分组默认值与旧groupId版本继承。
Ruling: 资料归组沿用原有前端持久化与权限边界；不新增后台自动发布或自动采用。原有未分组资料保留，归组通过显式编辑。
Ruling: 回复与历史条款共用存储，保存时合并最新快照，避免覆盖后台解析；有失败复现及通过回归。
