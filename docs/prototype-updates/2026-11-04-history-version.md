# 历史 RFQ 版本与比对

## 使用
1. 历史 RFQ → 上传历史 RFQ，选择“新增历史 RFQ”或“已有 RFQ 的新版本”。详情内上传默认关联当前文档。
2. 新版可填写客户版本标识和变更说明，留空按内部修订序号生成 V2、V3。相同内容在同族内复用原记录，相同版本标识拒绝新建。
3. 打开文档查看版本记录，点击“版本比对”，选择基准版和目标版。
4. 按变化类型筛选，查看要求、答复、适用条件的高亮差异；需要时打开两侧条款并定位原文。

## 边界
- 每版独立保存原件、条款和解析记录；重新解析不增加文档版本。已发布条款仍按原审核流程修订。
- 旧文档不要求迁移，各自作为独立版本族；新版本继承关联版可见范围。
- 匹配使用唯一相同要求与唯一编号，重复编号不强行关联；无法匹配项作为新增／删除并提示核对。未实现人工保存配对、语义匹配、拆分合并。
- 要求变更显示“需确认答复”，不自动沿用旧审核结论；提醒为比对结果，不是单独持久化复核任务。
- 比对以各文档当前最新内部条款修订为准；没有把每次比对保存为不可变报告。
- 数据继续沿用现有浏览器 localStorage 与 IndexedDB；没有新增共享后端存储。
