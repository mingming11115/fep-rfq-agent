# 三角色功能划分验证

## 本次落实

- 共享权限规则同时覆盖菜单、页面、按钮和操作回调；旧链接和新建 query 参数不能绕过职责。
- 销售：项目、来源上传/解析/补录/修正、起草提交、客户澄清、专业事项沟通与验收登记、导出模板映射及文件下载。
- 技术：专业方案、条款确认及建议采用、知识与机型能力候选、证据维护；应答编辑不能改客户原文。
- 最终审批人：方案与应答快照的批准/退回、资料审核发布和审计查询；应答、候选和证据只读。
- 销售/技术可提交快照，正式 CSV 仅销售可下载。业务资料与系统配置拆分，三个业务身份均无系统配置入口及访问权。
- 角色切换重建编辑表单；原有任务归属、版本和独立人员校验继续生效。旧专业处理任务按三角色规则归技术处理，历史完成记录保留。
- 补回现有应答编辑区缺失的对外答复、适用条件和证据输入，使用相同角色与任务校验。

## 验证证据

基线 86 项测试通过；最终全量 97/97 通过，生产构建及 `git diff --check` 通过（构建保留已有包体积提示）。新增角色策略、非法身份/动作/页面、来源字段防越权、专业处理及澄清职责、销售重开评审和独立沟通登记回归；均先观察失败后实现修复。

浏览器在独立 `localhost` 演示存储中新建“三角色权限验收-20261025”，未重置或更改用户 `127.0.0.1` 的项目内容，实际走通：

1. 销售创建、补录一条要求、填写应答和不适用依据、保存并提交技术确认；销售无法确认。
2. 技术接续并确认条款；来源操作、导出模板与下载只读；提交快照后无法自行批准。
3. 最终审批人退回并填写原因，技术重新提交新快照。
4. 独立审批人批准新快照，项目变为审批完成，审批人仍无法导出。
5. 销售生成真实正式 CSV，项目变为已导出。
6. 技术/审批角色无新建入口；`projects?action=create` 不展示创建表单，`admin` 旧地址被拒绝。
7. 销售知识只读，技术可维护候选及证据，审批人可撤销已发布机型但不能新建机型、编辑证据。
8. 销售可独立保存专业事项的沟通与验收记录，技术处理任务归属保持不变。

独立代码复核发现并修复两项问题：技术通过旧原文编辑抽屉改写来源，以及专业方案权限收紧后销售沟通记录无法保存。新增回归测试通过。

## 实现边界

本次为当前 React 本机原型的功能划分。文件解析仍使用演示数据，企业登录、服务端授权与多用户共享存储需要后续实现；本次保留现有工作区及浏览器历史数据。
