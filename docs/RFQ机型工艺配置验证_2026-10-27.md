# RFQ 机型与工艺配置验证

## 已实现

- “机型元数据 / 能力边界”采用 BU → 机型 → 工艺 → 能力条目。
- BU管理员配置本BU机型及下属工艺，机型修改保留资料版本；工艺支持启用、停用，停用保留历史关系。
- 技术和SR只读基础配置。技术维护能力候选；提交和发布校验本BU同机型的启用工艺及有效证据，保留独立审核资格和不可自审规则。
- 已有机型的硬件版本固定，新硬件版本须新增机型；项目补充显式选择机型与工艺，切换机型清空工艺。
- 没有工艺ID的旧能力保留为“待关联工艺”，不根据文字猜测。导入能力调整归属后再次导入也不会重复同一ID。

## 验证结果

- `node --test src/modelProcessDomain.test.js`：8项领域回归通过，覆盖管理员权限、跨BU、机型版本、工艺归属、停用、导入身份唯一性。
- `npm test`：当前工作区183项通过，0失败。
- `npm run build`：成功；保留现有前端包体积大于500kB的提示。
- `git diff --check`：通过。
- 独立浏览器会话验证：BU管理员新建机型与工艺、更新机型保留原版本、刷新恢复、两个BU使用相同编码而互不覆盖、SR及技术配置只读、工艺关联能力、重复导入和变更工艺后重导入去重、旧记录保留、停用后不能新增和批准发布、从能力详情进入编辑正常保存。无页面异常。
- 浏览器验收脚本：`/private/tmp/rfq-model-process-qa.cjs`；截图：`/private/tmp/rfq-model-process-qa.png`。
