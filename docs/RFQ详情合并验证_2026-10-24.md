# RFQ 详情与 Word 批注合并验证

## 本轮内容

- 项目详情默认基本信息，左侧常驻项目原文，右侧为基本信息、条款处理、评审澄清、历史版本、协作记录。
- 连续正文与 Word 风格纸张，目录按需展开；支持文件切换、缩放、显示应答。
- 条款处理保留应答编辑、匹配依据和批注讨论。选中原文可直接批注，保存后显示精确范围高亮；批注卡片、原文和连线同步定位。
- 批注使用统一项目存储，可回复、编辑、解决及转评审/澄清；旧固定 Word 示例保留独立入口，不将其内容误挂到其他文件。
- 历史文件记录使用项目文件清单；侧栏版本和评审表格适配为紧凑卡片。

## 验证证据

- `npm test`：75/75 通过，新增 5 项范围测试，覆盖重复文字、交叠批注、来源变化及项目/文件/版本隔离。
- `npm run build`：通过；静态包体积提示仍保留。
- `git diff --check`：通过。
- 浏览器：1280px 两栏，700px 上下排列；700px 页面宽度与 scrollWidth 均为 700，无横向溢出。
- 拖选安装条件中的部分文字，右侧自动切换至该条款批注；保存后仅高亮选中片段，刷新后保留。
- 切换侧栏前后原文 scrollTop 均为 403.5，阅读位置保持。
- 临时修改应答后切换分区触发保护；放弃后恢复保存内容。
- 旧来源版本链接切换基本信息/条款处理后仍只读。
- 销售编辑批注后切到最终审批人，编辑器与保存按钮消失，原批注未改变。
- 深链接初次打开定位目标条款；批注卡片定位保持批注页签。
- 在独立 localhost 演示存储验证空 RFQ，可显示基本信息与上传入口，不影响 127.0.0.1 的项目数据。
- 独立审查发现的四项 P2 已修复并通过浏览器复测：丢弃草稿、来源版本保留、批注编辑权限、首次原文定位。

## 边界

本轮实现界面与交互合并。左侧仍使用现有项目条款摘录，真实 PDF 可打开原件；未新增真实 Word 排版引擎、文件解析或 DOCX 导出。业务与批注继续在演示浏览器本地保存。
