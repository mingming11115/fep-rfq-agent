# RFQ 项目 Word / PDF 批阅接入

分支：`codex/rfq-craft-document-review`。详情左侧直接使用 WordCraft 0.13.2 / PdfCraft 0.16.1，批注卡片、回复、图标及连线复用已确认的 Demo；右侧继续使用现有协作记录。

## 本机入口

[RFQ-001 第 6 条](http://127.0.0.1:5174/#/response?projectId=RFQ-001&requirementId=RFQ-001-DOC-EXAMPLE-6)。首次打开「条款状态示例.docx / V1.0」会关联内置的真实 DOCX，已有上传文件优先。新入口与旧 `5173` 属于不同浏览器存储来源，因此各自保留业务演示数据。

RFQ-001 的商务 V1.1、技术 V2.0、状态矩阵 V1.0 也提供 Word 批阅演示文档，覆盖剩余
12 条模拟要求，切换示例卡片继续使用与独立 Demo 相同的 Word 编辑器和工具栏。
这些文档由现有模拟条款生成并明确标注为演示摘录，不代表客户的 Excel 或 PDF 原件。
已上传的文件或旧文件引用优先，不以演示文档替换；其他项目及其他来源版本不自动套用。

## 启动

Windows 可直接 `git pull` 获取预编译编辑器及 Java 后端运行包，按 [Windows 启动说明](windows-craft-startup.md) 启动；不需要另外下载 ZIP，也不需要 Rust、Maven 或 Docker。

可直接在仓库根目录用 Java 17+ 启动后端：

```sh
java -jar rfq-service/runtime/rfq-service.jar --server.port=48083 --office.storage-dir=./rfq-service/data/craft
```

也可以构建并启动 Docker 后端：

```sh
docker build -t rfq-craft-service:local rfq-service
docker run -d --name rfq-craft-service-local \
  -p 127.0.0.1:48083:48083 \
  -e SERVER_PORT=48083 -e SPRING_PROFILES_ACTIVE=local \
  -e ONLYOFFICE_STORAGE_DIR=/app/data/craft \
  -v rfq-craft-documents:/app/data rfq-craft-service:local
```

已创建的容器可用 `docker start rfq-craft-service-local` 重启。存储配置沿用原文件服务的变量名称，但原生编辑器不需要 ONLYOFFICE 容器。旧服务及旧文件卷继续独立保留。

前端：

```sh
cd rfq-react-prototype
npm ci
npm run dev -- --port 5174
```

Word/PDF 浏览器运行文件和校验清单已纳入 Git，`npm run dev` / `npm run build` 会自动校验并复制到 `public/craft-editors`，干净检出不需要编译。只有修改原生引擎后才需要 Rust 1.95、WASM target 与 wasm-bindgen 0.2.129 执行 `craft:build`，并连同生成资源、清单一起提交；固定源码、字体及补丁仍通过散列校验，见 [Demo 构建说明](../demos/craft-review/README.md)。构建缓存、前端生成副本和导出文件继续不入 Git。

`/api/craft` 默认代理到 `48083`，可用 `RFQ_CRAFT_API_TARGET` 调整；旧文件导入所用 `/api/office` 默认代理到 `48081`，可用 `RFQ_BACKEND_URL` 调整。发布生产构建时，需由部署服务器提供同源 `/api/craft` 路由；开发代理不会打包进静态产物。

## 操作与数据

- 文档顶部统一为单行：左侧为文件切换、来源版本及当前文件保存状态，右侧为唯一目录入口、点击展开的搜索与筛选、话术批注开关、条款摘录及放大。去掉重复文件标题；较窄区域保存状态以有完整说明的圆点显示。搜索和筛选共用弹层，Esc 收起时保留输入。目录和工具栏随文件区一起放大，操作不会重新打开编辑器或自动保存文件；文件切换、搜索和筛选继续执行既有未保存检查。
- Word 顶部含自动保存、快捷按钮、搜索、Discord 和头像的整行已去掉；下方“编辑／审阅”模式切换按钮也去掉。项目 Word 默认隐藏整排功能区并释放高度，点击文件工具栏的“编辑工具”开关显示标签及当前工具，再次点击完全隐藏。同一文件内切换条款保留选择，新文件或重新打开编辑器默认隐藏；条款摘录时禁用开关，PDF 不显示该 Word 开关。开关不修改正文、不触发保存，也不改变原有编辑/批注权限。独立 Demo 沿用原来的功能区行为。展开后统一隐藏 Zotero、开发工具、邮件、引用、布局、设计和文件七个标签，个人设置、重置及窄屏“更多标签”菜单不能恢复这些标签；其余普通和上下文标签继续可用。
- 目录统一使用工作区上方的一个“目录”入口，面板内切换“条款／文档标题”，默认显示条款。条款视图保留原始章节、处理状态、搜索、筛选、勾选和批量确认；文档标题视图读取当前真实 Word 文件的标题层级和编号，点击跳转。文件标题行不再重复提供目录按钮。没有标题、没有关联原件或 PDF 会显示对应提示，可切回条款视图。读取与跳转只改变视图和光标，不插入目录、不设置标题样式、不改变正文版本、撤销历史或未保存状态，也不触发保存；过期文件会话或标题版本的点击会被拒绝。
- 切换右侧条款会定位原文；点击已关联的文件批注会回到对应条款和协作记录。顶部定位图标可重新定位当前条款，成功提示显示 2 秒后整行收起，重复点击当前话术也会重新提示。找不到唯一原文、有歧义、不支持定位或仅跳到来源页时，保留提示及“重新定位／查看摘录”；加载中、无原件、无当前条款或条款摘录视图禁用定位。提示只对应当前文件和条款，视图更新不会延长成功提示，定位及查看摘录不修改或保存原文。
- 「话术批注」在原生 Word / PDF 旁显示本文件各条款的 Comply 或推荐话术，沿用原来的话术生成规则；右侧当前编辑中的条件、原因和结论实时预览。可按结论筛选、点击定位，窄区域中显示在编辑器下方。此处是应答预览，不会自动生成个人协作记录或写入文件批注。
- 点击话术会再次定位并高亮原文，连线使用编辑器返回的真实坐标，随滚动更新；点击已选中的话术也能重新定位。来源不匹配或定位有歧义时不画定位连线。
- 批注统一在右侧“协作记录”新增、修改、回复、解决/重开及按权限删除，继续保留 @提及和转评审。页边只显示作者、三行摘要、回复数量、解决状态及真实锚点/连线；点击打开右侧讨论，不再出现页边编辑框、回复框或操作菜单。原文选区的新建保留同一个原生锚点，只有这次新建的摘录能唯一匹配有权限条款时才关联；重复点击摘要不会清空正在输入的右侧内容。
- 无法唯一关联时，在右侧打开“文件批注 · 待关联条款”，可按原有权限编辑、回复、解决、取消/删除或明确选择条款，再同步到业务协作记录；原文区只保留“查看批注”入口。既有空白文件批注不会批量导入；点击后才进入待关联流程。原生编号复用不会恢复被删除的旧讨论或旧评审链接，普通撤销恢复既有批注仍保留。编辑请求处理一次后清除，切换分区再查看另一条摘要不会打开旧编辑框。独立 Demo 沿用原页边完整编辑。
- 进入“协作记录”即显示当前条款讨论或空状态，按当前文件及来源版本隔离。“项目成员、全部批注、操作记录”分别默认收起，点击或使用回车/空格按需展开；更新记录和同项目切换条款保留展开状态，新项目重新收起。“全部批注”继续支持跨条款定位及历史版本提示，操作记录沿用最近 30 条；查看与展开不修改业务数据或保存原文。验收见 [第 6 项验证记录](prototype-updates/2026-11-02-focused-discussion-verification.md)。
- SR 可编辑正文；条款处理人可在授权条款批注；只读身份不能新增或修改。外来批注保留原作者，不能改写他人的正文。身份与项目权限仍为演示机制，未接入企业认证。
- 业务协作记录及文件引用仍保存在当前浏览器。真实原件和批阅稿由后端文件卷保存，文件访问凭据随浏览器引用保留。清除浏览器数据会丢失该引用；当前尚无跨设备业务同步。
- Word/PDF 底部文件操作行（重开保存稿、原件、批阅版、保存原文）已去掉。原生快捷键 `Ctrl+S`（macOS `Cmd+S`）仍可保存真实批阅稿；保存队列及原有权限继续生效，文件标题说明显示保存中或未保存状态。仅在服务器确认且保存内容覆盖当前修改后清除未保存标记。保存失败时，错误提示提供「下载本地备份」「重新打开」；先下载备份再重新打开，避免覆盖较新版本。
- 后端分别保留初次上传的不可变原件和最新已保存批阅稿。重新打开时，文件正文及未关联批注以保存稿为准；已进入业务协作记录的待同步批注保留并重新应用。
- 历史 ONLYOFFICE 引用首次使用时导入原件及最新批阅稿，旧引用与文件保留。缺少原件时仍可查看条款摘录，由 SR 补传对应 DOCX / PDF。旧 DOC 须先转换为 DOCX。

文件批阅不会自动重新解析条款、修改应答结论或完成正式审批。当前解析和检索仍沿用原型模拟逻辑；批阅版下载也不等于经评审批准的正式对外导出。

## 验证入口

```sh
cd rfq-react-prototype
npm test
npm run build
```

仓库根目录运行 `node --test demos/craft-review/tests/*.test.mjs` 检查共享批注界面；后端 Docker 构建执行完整 Maven `verify`。原生桥在 Rust 定向测试中验证定位、幂等写入、权限及真实文件保存后重开。

本机已完成实际浏览器验收，结果和截图见验证记录；Windows 系统未在本机运行验证。引擎仍是固定版本的上游项目，复杂 Office 排版、PDF 字体和第三方批注应使用实际客户文件补充人工验收。

本次结果和已知检查限制见 [验证记录](prototype-updates/2026-11-01-craft-project-review-verification.md)。
