# 本机 MySQL 数据版本启用记录

本次将 `origin/codex/mysql-workspace-sync`（a99941d）快进合入 master，启用原工作台的数据库读取入口。

## 本机服务

- 前端：http://127.0.0.1:5173
- 新版后端：容器 `rfq-mysql-workspace`，端口 48084。
- MySQL：沿用 `rfq-mysql-local` 的 `rfq` 数据库；原件沿用 `rfq-craft-documents` 卷。
- 示例销售账号：`mysql_sr`，初始密码 `Rfq@2026`。原有账号不自动取得新演示 BU 的授权。
- 后端再次启动：`docker start rfq-mysql-workspace`；前端：工程根目录 `npm run dev`。

迁移前数据库备份位于本机 `/private/tmp/rfq-before-mysql-sync.sql`。不要把该备份提交到版本库。

本机没有 Java/Maven，使用现有 Maven 镜像的 Java 17 和历史运行包依赖编译全部源码（保留 `-parameters` 元数据），更新应用类及资源后部署。正常开发仍应安装 Java 17/Maven 并按 README 构建；此次未宣称标准 Maven 构建通过。

## 尚未完成的范围

这次启用的是已有分支的数据库读取实现，不是全部业务读写迁移完成：

- 应答编辑、确认、审批、部分项目配置和知识维护等尚缺写入接口，数据库模式中仍被禁用。
- 工作台任务、分析记录、评论等没有完整的数据库加载与持久化实现。
- 未导入各浏览器以前手工修改的 localStorage / IndexedDB 数据；旧数据未清除。
- 文件原件保存在文件卷，MySQL 保存其登记信息及关联；历史证据元数据不代表存在证据原件。

后续补齐写操作必须使用服务端权限校验、事务和版本冲突检查，不能仅移除前端禁用判断，也不能用整份浏览器状态覆盖共享数据库。
